# Contributing and reporting issues

This repository supports a source-checkout workflow. Start with the data-free tests; model weights and datasets are not needed:

```bash
python -m pip install -e ".[test]"
python -m unittest discover -s tests -v
python scripts/check_release.py
python scripts/doctor.py --mode source
```

Use a separate environment for the complete application because its OpenCV package differs from the headless test dependency. See [setup](docs/SETUP.md).

For a bug report, include your operating system, Python version, installation command, the failing command and a sanitized traceback. Use the fictional image generated by `scripts/generate_example.py` when possible. Never attach company images, labels, predictions, credentials or unapproved weights to an issue.

Keep pull requests focused on one behavior. Explain the problem, resulting behavior and validation. Add a regression test for behavior changes; documentation-only changes do not require new tests. Preserve the OCR input contract, dictionary ordering and historical model hashes. Register a new export under a new model name rather than replacing a historical checkpoint.

Run the public inventory check before publishing. Newly introduced public files must be explicitly included in `scripts/check_release.py`; do not broaden it to include raw data, model binaries or run reports. Publication-profile builds are local previews, not authorization to disclose additional material.

Original-code licensing remains undecided. Publication of source does not establish a blanket license for the repository, dependencies, weights or datasets. See [third-party notices](docs/THIRD_PARTY_NOTICES.md).
